Examples

Three runnable ones ship in the repo. Two need no API key at all, and the third has a test harness of fourteen suites that runs without a model.

1. The pipeline: coordination with no routing table

deno task demo

A planner fans a job out into per-word tasks, two workers claim only the operations they can handle, and an aggregator reads the results and writes one summary. Nothing imports anything else. Deterministic, no model, no flakiness.

2. The chat: a whole agent, as records

deno task chat

A CLI chatbot where thinking, acting, drawing, executing code and saving files all flow through the space. Six worker processes, each with its own credential and its own OS permissions. The REPL makes no external calls; it only reads and writes records.

one turn, as records
message      // what you typed
llm_call     // untiered: the REPL does not pick a model
  llm_call   // a router-worker picks the tier and re-posts
  llm_chunk  // streamed tokens, as records
  llm_result
tool_call    // whichever worker advertised that tool claims it
  progress
  tool_result
  check      // a verdict the model has no grant to write

Because the conversation is records, it survives a restart, resumes by id, and can be inspected by anyone with a grant. The file-reading worker holds --allow-read and no --allow-env, so reading a file cannot lead to exfiltrating it.

Fourteen smoke suites, no API key. A tool call is a record and the context assembly is a pure function, so the suites drive the real queries and the real window expansion with no model. This is where bugs surface first.

3. The console

Served at / by the dev space, using only the public API.

Feed streams the event log. Graph draws the parent_ids DAG around a record. Space places every record by what it is rather than what it links to. Auth mints a person's session and shows the bootstrap chain as the records it is.

The view lives in the URL, so any of it is a link you can send, and it survives the credential expiring mid-investigation.

4. Flows: the workflow diagram nobody wrote

Nothing declares a topology, so the shape has to be mined.

A content-routed space cannot render its own process, because there is no process to render. What exists is what happened. So each causally connected subgraph is abstracted to the sequence of kinds and agents at each depth, and the results are grouped.

radia flows
 180x  100%  n= 2     1.3s  llm_call → llm_result
 104x  100%  n= 7     7.6s  conversation ⇒ llm_call → llm_call + message → llm_result
  73x  100%  n= 4   810ms  conversation ⇒ tool_call → message + tool_result
   3x  100%  n=10   229ms  job → task×4-7 → result×4-7 → summary

The last row is the pipeline above, recovered without the miner being told to look for it. Shapes that start and rarely finish are listed beside the ones that complete, because that comparison is the signal: an orphaned record whose kind nothing listens for needs a different fix from one whose worker is simply down.
